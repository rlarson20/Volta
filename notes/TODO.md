- [x] Pick one error regime, document it in `dev-docs/DEVELOPMENT.md`, and prune redundant `try_*` variants (2026-10-31). Decided by where the data comes from; recorded in DECISIONS.md, `dev-docs/DEVELOPMENT.md`, and CLAUDE.md invariant 8. Nothing was pruned: all nine existing `try_*` take an argument that can come from outside (`Axis(pub usize)` is not validated, so a user-chosen axis needs `try_sum_dim`). `to_one_hot` is a `Result`; `binary_backward_broadcast_safe`'s rank > 4 panic stays (H5; unreachable, and its input is a tensor the program built).
- [ ] **Make `load_state_dict` atomic before any browser tool uses it.** It checks each entry as it reaches it, so a bad entry in layer 3 of 5 returns `Err` after layers 1 and 2 were overwritten, and a UI that shows "load failed" and keeps the model is running mixed weights. Do it as **plan, then apply**: each layer returns the `(tensor, entry)` pairs it would load (`Rc` handles and references, no weight copies), and a provided trait method checks every pair's shape and length before writing any. Nothing is written until the whole load is known to succeed, and that is the only option with no memory cost. Do not use snapshot-and-rollback or a fresh model plus a swap: both keep the old values alive, so peak memory is about twice the weights, which is gigabytes for a large model and can crash a browser tab on the path meant to be safe. Validating up front against `self.state_dict()` is not airtight either (`Sequential` accepts a layer name or an index as prefix, and mapped keys need not match what `state_dict()` emits) and it clones every weight. Plan-then-apply rewrites the roughly ten layers that load weights (the no-op layers keep their bodies), makes the apply step infallible (a GPU upload failure there would have to panic or be handled separately), and lets containers prefix keys while collecting, which would retire `VoltaError::with_key_prefix`. It changes the `Module` trait a second time, so do it together with the browser tool, not before.
- [ ] Ops that take a user-chosen `Axis`, `permute` order, or padding/shrink ranges (`max_dim`, `mean_dim`, `softmax`, `log_softmax`, `permute`) panic on a bad value and have no `try_` form (only `sum_dim`, `pad_with`, `shrink` do). A WASM binding has to range-check against `shape().rank()` itself. Add a `try_` form, or an `Axis::new(dim, rank)`, when the binding exists.

Also unverified for wasm32: `std::fs`/`std::time` use in `io` and `utils`, and the `accelerate` feature (macOS-only). The WASM binding (`pkg/`, `minigrad-react/src/wasm/`) is an untracked build of code that is not in this repo, so nothing here is tested against it. Add a wasm32 `cargo check` to CI once the target builds.
